Local code knowledge for agents

Structure before you edit.

Cortex turns a repository into a local semantic graph so agents can answer structural questions before they edit code: who owns this symbol, who calls it, what depends on it, and what is the likely blast radius of a change.

Answer structural questions directly

Resolve symbol ownership, callers, dependencies, references, and bounded impact without manually walking grep output.

Keep everything local

Cortex builds and queries a persistent graph on your machine. No hosted service, remote index, or vendor lock-in is required.

Designed for agent workflows

Use the CLI for one-off orientation or keep the daemon warm for editors, automations, and coding agents that need repeated graph lookups.

Benchmark-backed, not hand-waved

The repository includes a reproducible benchmark harness and published artifacts comparing Cortex against a raw text-search baseline.

Install

Install Cortex fast.

Use the release installer for a local binary, or build from source if you want to hack on the monorepo.

macOS / Linux curl -fsSL https://raw.githubusercontent.com/Blu3Ph4ntom/cortex/main/scripts/install.sh | sh
Windows (PowerShell) irm https://raw.githubusercontent.com/Blu3Ph4ntom/cortex/main/scripts/install.ps1 | iex
Build from source git clone https://github.com/Blu3Ph4ntom/cortex.git cd cortex cargo install --path crates/cortex-cli cargo install --path crates/cortex-daemon
Install target

Release installers place binaries in a common local path: ~/.local/bin on Unix and $HOME\.cortex\bin on Windows.

Windows note

Use the MSVC Rust toolchain if your GNU toolchain does not ship gcc.exe and dlltool.exe.

Quick start

Index once, query before you edit.

The common agent loop is simple: build the graph, resolve the owner, inspect callers, then check blast radius.

Index a repository cortex index --repo /path/to/repo
Resolve a symbol owner cortex query --repo /path/to/repo find-symbol --name RepositorySession
Check callers before a change cortex query --repo /path/to/repo callers --target open_session
Inspect dependencies and blast radius cortex query --repo /path/to/repo dependencies --target RepositorySession --direction both --depth 1 cortex query --repo /path/to/repo impact --target open_session --depth 1
Agent workflows

Use it where agents usually guess.

Pre-edit orientation

Resolve the canonical owner of a symbol before an agent starts patching an unfamiliar codebase.

Refactor safety checks

Ask for callers and dependencies first, then make the signature or behavior change with less blind risk.

Review context

Attach structural neighbors and likely impact to a patch review so the summary is grounded in code relationships, not filename guesses.

Local automation

Let local automation, editors, or daemon clients query the graph repeatedly without rebuilding context from scratch every turn.

Good fit

Repository orientation, targeted edits, change review, bounded blast-radius checks, and machine-readable architecture discovery.

Not a fit

Compiler-grade proof, runtime data-flow certainty, or framework magic that only resolves through execution.

Query model

The surface area is small on purpose.

find-symbol

Resolve the canonical owner candidate for a symbol and get back a file path plus span.

callers / callees

Walk into the call chain before you change behavior or when you are tracing outward from a function.

dependencies

Inspect the local inbound and outbound structural neighborhood around a symbol or file.

references / impact / explain

Get conservative reference sets, likely blast radius, and a summary of why a symbol matters in the current graph.

Owner lookup cortex query --repo /path/to/repo find-symbol --name PaymentService
Caller trace cortex query --repo /path/to/repo callers --target update_status
Explain a symbol cortex query --repo /path/to/repo explain --target PaymentService

What it teaches an agent

Sequence

Index the repo, resolve the owner, inspect callers or dependencies, then run impact before the edit lands.

Reporting

Quote the resolved file path and span, distinguish confirmed structure from inference, and mark dynamic behavior as uncertain.

Boundaries

Use Cortex for structural truth; fall back to direct code reading when runtime behavior or framework indirection matters more than syntax.

Methodology

Cold index medians come from fresh stores. Warm-query medians reuse a prepared local store. The baseline is raw repo search, not a compiler or a proprietary SaaS tool.

Artifacts

Benchmark report and benchmark JSON ship in the repository.

Daemon API

Keep the graph warm for tools.

Use the local daemon when another process needs repeated access without shelling out for each query.

Start the daemon cortexd --repo /path/to/repo --bind 127.0.0.1:8787
Resolve a symbol over HTTP curl "http://127.0.0.1:8787/graph/find_symbol?name=RepositorySession"
Ask for callers over HTTP curl "http://127.0.0.1:8787/graph/callers?target=open_session"
Architecture

A small Rust monorepo with hard boundaries.

cortex-core

Holds the graph model, parser extractors, indexer, storage layer, and query engine.

cortex-cli

Exposes indexing, doctor, export, watch, and query commands for local use and scripting.

cortex-daemon

Serves the same structural answers over local HTTP for tools that want a long-lived process.

Semantic shape

Today the graph tracks repositories, files, symbols, and edges such as defines, contains, imports, references, calls, depends_on, and owned_by.

Current tradeoff

Cortex is intentionally conservative and syntax-driven. That is enough to make it useful for navigation and pre-edit context, but not enough to claim compiler-grade semantic truth.
