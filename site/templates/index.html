Codebase memory for agents.

Cortex is a local-first code knowledge engine that turns a repository into a persistent semantic graph so agents can resolve symbol ownership, inspect callers, trace dependencies, and estimate impact with structural context instead of grep and guesswork.

Get Started GitHub

Local graph store

No hosted service required. Cortex builds and persists the semantic graph on your machine and queries it in-place.

Structural queries

Ask for symbol ownership, callers, references, dependencies, and bounded impact instead of grepping for identifiers.

Polyglot support

Indexes Rust, JavaScript, TypeScript, Python, and Go repositories from one local workspace and normalizes them into one graph.

CLI and daemon

Use the CLI directly or expose the graph through a local HTTP daemon for agents, editors, and automation flows.

Install

One-line installer

Detects OS and architecture, downloads the latest release binary, and installs it to a common local path.

macOS / Linux curl -fsSL https://raw.githubusercontent.com/Blu3Ph4ntom/cortex/main/scripts/install.sh | sh
Windows (PowerShell) irm https://raw.githubusercontent.com/Blu3Ph4ntom/cortex/main/scripts/install.ps1 | iex

Build from source

macOS / Linux / Windows git clone https://github.com/Blu3Ph4ntom/cortex.git cd cortex cargo install --path crates/cortex-cli cargo install --path crates/cortex-daemon

Quick start

Index a repository, then query the graph for ownership and blast radius before you edit code.

cortex index --repo /path/to/repo
cortex query --repo /path/to/repo find-symbol --name RepositorySession
cortex query --repo /path/to/repo callers --target open_session
cortex query --repo /path/to/repo dependencies --target RepositorySession --direction both --depth 1

Agent workflows

Pre-edit orientation

Resolve the actual owner of a type, helper, or module before the agent starts editing an unfamiliar repository.

Refactor safety

Ask who calls a symbol and what depends on it before renames, extractions, or signature changes.

Patch review context

Surface nearby callers, callees, and references so review summaries are grounded in structure rather than filename guesses.

Local toolchain integration

Use the daemon from agents, editors, and automation without standing up a hosted graph service.

Query model

  • find-symbol <name> — resolve the canonical owner of a symbol
  • dependencies <target> — inspect inbound and outbound structural neighbors
  • callers <target> — find the functions or commands that invoke a helper
  • callees <target> — walk outward from a function into what it invokes
  • references <target> — inspect best-effort identifier references
  • impact <target> / explain <target> — summarize likely blast radius and structural context

Daemon API

Run the local HTTP daemon when another process needs repeated graph access without shelling out for every query.

cortexd --repo /path/to/repo --bind 127.0.0.1:8787
curl "http://127.0.0.1:8787/graph/find_symbol?name=RepositorySession"
curl "http://127.0.0.1:8787/graph/callers?target=open_session"

Architecture

Core crates

  • cortex-core — indexer, graph store, extractors, and query engine
  • cortex-cli — local command-line interface
  • cortex-daemon — local HTTP serving layer

Current tradeoff

The graph is intentionally conservative and syntax-driven. It is already useful for navigation, review context, and bounded impact analysis, but it is not compiler-grade proof.
