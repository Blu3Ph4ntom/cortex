How it works

A local pipeline with a durable graph at the center.

  1. Parse supported files. Cortex extracts normalized symbols and relations from Rust, JS/TS, Python, and Go.
  2. Materialize the graph. Files, symbols, and edges become a queryable local knowledge layer.
  3. Keep it live. Index refresh updates the graph so the memory stays aligned with the repository.
  4. Query from tools. The CLI and daemon expose stable query families that agents can consume directly.

Real scenarios

Actual queries you can run right now.

Find the owner of a core type

Use `find-symbol` when you know a symbol name but not the file that truly defines it.

cortex query --repo . find-symbol --name RepositorySession

Check callers before changing a helper

Use `callers` to see which user-facing flows will feel a local implementation change.

cortex query --repo . callers --target open_session

Inspect structural blast radius

Use `dependencies` when you need the immediate inbound and outbound neighborhood around a type or function.

cortex query --repo . dependencies --target RepositorySession --direction both --depth 1
